# Schema Conventions

Standard conventions for all Supabase/PostgreSQL tables in this project.

---

## Naming Rules

| Target | Convention | Example |
|--------|-----------|---------|
| Table names | `snake_case`, plural | `products`, `order_items`, `user_profiles` |
| Column names | `snake_case`, singular | `first_name`, `product_id`, `created_at` |
| Index names | `idx_[table]_[col]` | `idx_products_user_id` |
| FK constraint | `fk_[table]_[col]` | `fk_products_category_id` |
| Policy names | `"[table]_[action]_[scope]"` | `"products_select_own"` |
| Trigger names | `handle_updated_at` | same for all tables |
| Enum types | `snake_case` | `order_status`, `user_role` |

---

## Required Columns — Every Table

Every table must have these four columns:

```sql
id         uuid        DEFAULT gen_random_uuid() PRIMARY KEY,
created_at timestamptz DEFAULT now() NOT NULL,
updated_at timestamptz DEFAULT now() NOT NULL,
```

For user-owned tables, add:
```sql
user_id    uuid        REFERENCES auth.users(id) ON DELETE CASCADE NOT NULL,
```

For workspace/team-scoped tables, add:
```sql
workspace_id uuid      REFERENCES public.workspaces(id) ON DELETE CASCADE NOT NULL,
```

---

## Column Ordering

Always order columns in this sequence:
1. `id` — primary key first
2. Ownership FK — `user_id`, `workspace_id`, or equivalent
3. Other FK columns — references to related entities
4. Core data columns — the actual business fields
5. Status/flags — `status`, `is_active`, `is_deleted`
6. Timestamps last — `created_at`, `updated_at`

```sql
CREATE TABLE public.products (
  -- 1. PK
  id              uuid         DEFAULT gen_random_uuid() PRIMARY KEY,
  -- 2. Ownership FK
  user_id         uuid         REFERENCES auth.users(id) ON DELETE CASCADE NOT NULL,
  -- 3. Other FKs
  category_id     uuid         REFERENCES public.categories(id) ON DELETE SET NULL,
  -- 4. Core business columns
  name            text         NOT NULL,
  price           numeric(10,2) NOT NULL,
  size            text,
  color           text,
  description     text,
  thumbnail_url   text,
  -- 5. Status/flags
  is_available    boolean      DEFAULT true NOT NULL,
  -- 6. Timestamps
  created_at      timestamptz  DEFAULT now() NOT NULL,
  updated_at      timestamptz  DEFAULT now() NOT NULL
);
```

## Primary Keys

Always use UUID generated by `gen_random_uuid()`:

```sql
id uuid DEFAULT gen_random_uuid() PRIMARY KEY
```

**Never use:**
- `SERIAL` / `BIGSERIAL` (integer auto-increment) — predictable, exposes row count in URLs
- `uuid_generate_v4()` — requires uuid-ossp extension; `gen_random_uuid()` is built-in since PostgreSQL 13

---

## Timestamps

```sql
-- Always use timestamptz (timezone-aware), never timestamp
created_at timestamptz DEFAULT now() NOT NULL,
updated_at timestamptz DEFAULT now() NOT NULL
```

Auto-update `updated_at` with a custom trigger function. Never use `CREATE EXTENSION` (Supabase extensions are pre-installed) and never name the function `moddatetime()` (conflicts with the Supabase built-in extension):
```sql
-- Define once per migration (shared across all tables in the file)
CREATE OR REPLACE FUNCTION handle_updated_at()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- One trigger per table
DROP TRIGGER IF EXISTS set_updated_at ON public.[table_name];
CREATE TRIGGER set_updated_at
  BEFORE UPDATE ON public.[table_name]
  FOR EACH ROW
  EXECUTE FUNCTION handle_updated_at();
```

## NULL vs NOT NULL

Default to `NOT NULL` for required fields. Use nullable only when:
- The field is genuinely optional in the UI (user may leave it blank)
- The value is set asynchronously after initial insert (e.g. processed_at)
- It's a self-referential nullable FK (e.g. `parent_id` for nested comments)

```sql
-- Required: NOT NULL
name  text NOT NULL,
price numeric(10,2) NOT NULL,

-- Optional: nullable (no keyword needed, nullable is default)
description text,
discount_price numeric(10,2),
```

---

## Default Values

| Column type | Default |
|------------|---------|
| Boolean flags | `DEFAULT false` |
| Status fields | `DEFAULT 'pending'` (or first enum value) |
| Counters | `DEFAULT 0` |
| Arrays | `DEFAULT '{}'` |
| JSONB | `DEFAULT '{}'` or `DEFAULT '[]'` |
| Timestamps | `DEFAULT now()` |

## Schema: Always `public`

All tables go in the `public` schema unless there's a specific reason for isolation. Always prefix with `public.` in:
- REFERENCES clauses: `REFERENCES public.categories(id)`
- Policy definitions
- Index creation

## Constraints

### CHECK constraints (preferred over enums for dynamic values)
```sql
size    text CHECK (size IN ('XS', 'S', 'M', 'L', 'XL')),
status  text CHECK (status IN ('active', 'inactive', 'archived')) DEFAULT 'active',
rating  smallint CHECK (rating BETWEEN 1 AND 5),
```

### UNIQUE constraints
```sql
slug    text NOT NULL UNIQUE,
email   text NOT NULL UNIQUE,
-- Composite unique
UNIQUE (user_id, product_id)  -- e.g. a user can only have one review per product
```

### NOT NULL + UNIQUE = natural unique identifier
```sql
code    text NOT NULL UNIQUE,  -- e.g. product SKU, invite code
```

## Indexes — Always 1, more only if the requirement explicitly needs it.

**RULE: Every table gets exactly 1 default index. Only add extra indexes when the requirement explicitly calls for it.**

### The 1 default index (always add)

| Table type | Default index |
|---|---|
| User-owned table (has `user_id`) | `CREATE INDEX ON table(user_id)` |
| Public table (no `user_id`) | `CREATE INDEX ON table(created_at DESC)` |

```sql
-- ✅ User-owned — index user_id
CREATE INDEX IF NOT EXISTS idx_todos_user_id ON public.todos(user_id);

-- ✅ Public table — index created_at for ordering
CREATE INDEX IF NOT EXISTS idx_todos_created_at ON public.todos(created_at DESC);
```

> All index names follow the `idx_[table]_[col]` format. Never use `[table]_[col]_idx` — the naming table above is the canonical rule.

### Extra indexes — only when explicitly required
Add a second (or more) index only when the requirement clearly states filtering or sorting on a specific high-cardinality column. If the requirement does not mention it — do not add it.

### Hard stops — never index these no matter what

```sql
-- ❌ NEVER — boolean
CREATE INDEX ON todos(completed);
CREATE INDEX ON todos(is_active);

-- ❌ NEVER — low-cardinality enum/status (< ~15 distinct values)
CREATE INDEX ON todos(priority);
CREATE INDEX ON todos(status);
CREATE INDEX ON todos(role);

-- ❌ NEVER — composite indexes
CREATE INDEX ON todos(user_id, completed);
CREATE INDEX ON todos(user_id, priority);
CREATE INDEX ON todos(user_id, due_date);

-- ❌ NEVER — UNIQUE columns (already indexed by the UNIQUE constraint)
CREATE INDEX ON todos(slug);
CREATE INDEX ON todos(email);
```

### Never add a redundant index on UNIQUE columns
`UNIQUE` automatically creates a unique index in Postgres. Do NOT add a separate `CREATE INDEX` for it.

## Soft Deletes (when needed)

If the FE requirement includes "archive" or "trash" functionality:
```sql
deleted_at timestamptz,  -- NULL = not deleted, timestamp = soft-deleted
```

Add partial index for active-record queries:
```sql
CREATE INDEX idx_products_user_id_active ON public.products(user_id)
  WHERE deleted_at IS NULL;
```

Add RLS to filter deleted rows:
```sql
USING ((SELECT auth.uid()) = user_id AND deleted_at IS NULL)
```
