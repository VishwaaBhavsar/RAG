# Theme Factory Skill

Auto-select or generate production-ready themes with Tailwind v4 CSS variables. Uses OKLCH color space for perceptual uniformity and guarantees WCAG accessibility compliance.

## Core Principles

1. **No Questions**: Auto-select theme based on project context
2. **Web-Informed Direction**: Use `WebSearch` findings for domain palette/trend context when available
3. **OKLCH Colors**: Perceptually uniform color space
4. **60-30-10 Rule**: Balanced color distribution
5. **WCAG Compliance**: Built-in AA/AAA verification
6. **Tailwind v4**: Native @theme directive format

## Input

Context from previous skills:

```yaml
context:
  projectType: landing | dashboard | ecommerce | saas | portfolio | blog
  audience: b2b | b2c | developer | creative
```

### Step 3: Generate Color System

Reference: `references/color-system.md`

Apply OKLCH color space and 60-30-10 distribution rule.

### Step 4: Verify Accessibility

Reference: `references/accessibility.md`

Ensure all color combinations meet WCAG AA (4.5:1 for text).

### Step 5: Output Theme CSS

When `global.css` already exists, do NOT skip generation:

- replace only generated theme marker sections
- keep non-theme CSS unchanged
- ensure both light and dark theme tokens are updated in the same run

## Auto-Write to global.css

**IMPORTANT**: This skill automatically writes/refreshed the generated theme to `apps/frontend/src/app/global.css`.

### Target File
```
apps/frontend/src/app/global.css
```

### Write Behavior

The template uses OKLCH colors natively with clear section markers. When generating a theme:

1. **Find theme color section** - Look for `/* THEME COLORS - GENERATED BY theme-factory */`
2. **Replace until end marker** - Replace content until `/* END THEME COLORS */`
3. **Find gradients section** - Look for `/* GRADIENTS & EFFECTS - GENERATED BY theme-factory */`
4. **Replace until end marker** - Replace content until `/* END GRADIENTS & EFFECTS */`
5. **Preserve everything else** - Keep `@import`, animations, base styles, custom utilities
6. **Do this every theme run** - even if `global.css` already exists

### File Structure (OKLCH Native)

```css
@import 'tailwindcss';

@theme {
  /* =============================================
     THEME COLORS - GENERATED BY theme-factory
     ============================================= */

  /* Semantic Colors (OKLCH) - Direct values, no conversion needed */
  --color-background: oklch(12% 0.02 250);
  --color-foreground: oklch(95% 0.01 250);
  --color-primary: oklch(60% 0.15 250);
  /* ... all color tokens */

  /* Sidebar Colors */
  --color-sidebar: oklch(14% 0.02 250);
  /* ... */

  /* =============================================
     END THEME COLORS
     ============================================= */

  /* Radius - PRESERVED */
  --radius-sm: 0.25rem;
  /* ... */

  /* Animations - PRESERVED */
  /* ... */
}

@layer base {
  /* Global styles - PRESERVED */
}

/* =============================================
   GRADIENTS & EFFECTS - GENERATED BY theme-factory
   ============================================= */
@layer utilities {
  .gradient-primary { background: linear-gradient(...); }
  .shadow-glow { box-shadow: ...; }
  /* ... */
}
/* =============================================
   END GRADIENTS & EFFECTS
   ============================================= */

@layer utilities {
  /* Custom utilities - PRESERVED */
}
```

### Write Process

```yaml
steps:
  1. Read current global.css
  2. Find marker: "/* THEME COLORS - GENERATED BY theme-factory */"
  3. Replace until: "/* END THEME COLORS */"
  4. Insert OKLCH colors from selected theme
  5. Find marker: "/* GRADIENTS & EFFECTS - GENERATED BY theme-factory */"
  6. Replace until: "/* END GRADIENTS & EFFECTS */"
  7. Insert gradient utilities from theme
  8. Ensure both light and dark token variants are refreshed
  9. Write updated global.css
  10. Log: "Theme '{name}' written to global.css"
```

## Color Token Structure

| Category | Tokens | Purpose |
|----------|--------|---------|
| Primary Scale | `--color-primary-50` to `--color-primary-950` | Full 11-step scale from lightest to darkest |
| Semantic | `background`, `foreground`, `muted`, `border`, `ring`, `input` | Base UI tokens |
| Actions | `primary`, `secondary`, `accent` (+ `-foreground` variants) | Interactive elements |
| Status | `destructive`, `success`, `warning`, `info` | Feedback states |
| Sidebar | `sidebar`, `sidebar-foreground`, `sidebar-primary`, etc. | Navigation area |

## OKLCH Color Format

```css
/* Format: oklch(lightness chroma hue) */
--color-primary: oklch(55% 0.15 250);
```

| Component | Range | Description |
|-----------|-------|-------------|
| Lightness | 0-100% | 0% = black, 100% = white |
| Chroma | 0-0.4 | 0 = gray, higher = more saturated |
| Hue | 0-360° | Color wheel position |

**Benefits**: Perceptually uniform, predictable lightness for accessibility, P3 display support, independent L/C/H adjustment.

## Create Your Own Theme

When none of the pre-built themes fit the project context:

1. **Analyze Requirements** - Identify brand colors, mood, and target audience
2. **Generate OKLCH Palette** - Create primary/secondary/accent scales following 60-30-10 rule
3. **Select Typography** - Choose complementary heading/body font pairing
4. **Verify Contrast** - Ensure all pairs meet WCAG AA (4.5:1 minimum)
5. **Create Theme File** - Add to `themes/` directory following the template below

### Custom Theme Template

```markdown
# Theme Name

One sentence description.

## Color Palette (OKLCH)

| Token | Value | Usage |
|-------|-------|-------|
| background | oklch(12% 0.02 HUE) | Page background |
| foreground | oklch(95% 0.01 HUE) | Primary text |
| primary | oklch(60% 0.15 HUE) | CTAs, links |
| primary-foreground | oklch(100% 0 0) | Text on primary |
| secondary | oklch(20% 0.02 HUE) | Secondary elements |
| muted | oklch(18% 0.02 HUE) | Disabled, subtle |
| accent | oklch(65% 0.18 ACCENT_HUE) | Highlights |
| destructive | oklch(55% 0.22 25) | Errors, danger |

## Typography
- **Headings**: Font Name
- **Body**: Font Name

## Best For
Use case list.
```
